# Phase 9 — отчёт (оптимизация + удаление Go)

Дата: 2026-07-23. Ветка: `claude/magitrickle-c-rewrite-phase-0-t7iwas`.
Go backend (`src/backend`) **удалён в этой фазе** — единственная фаза
рерайта, в которой это разрешено (migration-plan.md, spec §23/§24).

## Выполнено

### Профилирование и оптимизация (задача #53)

- Профилирование полного пайплайна C-демона под нагрузкой (`valgrind
  --tool=callgrind`, `perf` недоступен для ядра этой песочницы —
  6.18.5, нет подходящего пакета `linux-tools`).
- Найденные и устранённые узкие места задокументированы в
  `decisions.md` (запись перед D-44 в этом файле): единственный
  реальный кандидат на оптимизацию — allocator overhead на запрос,
  явно помечен как **не требующий действия** — те же замеры (задача
  #54) показывают, что C уже существенно превосходит Go по throughput
  и CPU/RSS при равной нагрузке, так что "исправление" добавило бы
  сложность (arena allocator, риск use-after-free) без показанной
  потребности — прямое нарушение правила проекта "никакой сложности
  без доказанной необходимости" (spec §4/§23).

### Финальное сравнение C vs Go (задача #54)

- Полный пайплайн (не только транспорт), после исправления одной
  реальной порчи результатов (конкурентная пересборка
  `src/backend-c` во время работающего в фоне бенчмарка исказила
  часть чисел — переисполнено набело).
- Результат на ячейке rules=1000, concurrency=10: **C ~42k rps при
  ~66% CPU против Go ~20k rps при ~148% CPU**, RSS у C примерно вдвое
  ниже. Сырые данные — `docs/c-rewrite/baseline-raw-c/`.

### Долгий soak + финальные санитайзер/fuzz прогоны (задача #55)

- 180-секундный ограниченный soak (замена реального 24-часового
  прогона, тот же паттерн раскрытия ограничения, что и в D-36):
  500 namespace-правил, **3 023 131 UDP + 389 421 TCP запросов, ноль
  ошибок, ноль таймаутов**. RSS — плоская линия на всех 13 замерах по
  15 секунд (31 928 KB), `VmHWM` равен steady-state — ни утечки, ни
  временного всплеска. Результат — `docs/c-rewrite/soak-c-phase9/`.
- `make test` (все юнит-бинарники), `make sanitize` (0 находок
  ASan/UBSan), `make fuzz FUZZ_RUNS=200000` (2 цели, 400 000 прогонов,
  0 крашей), `tests/differential/run_diff.sh` (все наборы OK) — все
  чисто на свежепересобранном дереве.

### Чеклист паритета (задача #56)

- `docs/c-rewrite/parity-checklist.md` — построчный проход всех 11
  разделов `compatibility-contract.md` с вердиктами и ссылками на
  конкретные доказательства (юнит-тесты, дифференциальные наборы,
  контракт-тесты, отчёты предыдущих фаз).
- В процессе найден и исправлен один реальный, ранее не пойманный
  пробел паритета: список игнорируемых интерфейсов Keenetic
  (`ezcfg0`, `ra0`..`ra15`) не был перенесён в C — добавлен в
  `src/api/app.c` под `#ifdef MT_ENTWARE_KN` с тестом
  (`test_system.c`), подтверждающим поведение в обоих режимах сборки.
- Открыто зафиксированные остаточные пробелы (не устранены в этой
  фазе, так как физически недостижимы в песочнице): ни разу не было
  реальной on-device проверки на Entware/OpenWrt ни в одной фазе
  рерайта; поиск хука Keenetic RCI отложен, а не найден.

### Удаление Go backend (задача #57) — отдельное изменение

Выполнено по явной авторизации пользователя ("Yes, proceed now") после
показа чеклиста паритета и оставшихся оговорок. Полная мотивация и все
механические детали — `decisions.md` **D-45**. Сводка:

- **`src/backend` (Go, 85 файлов, ~572K) удалён** (`git rm -r`) вместе
  со всеми Go-модулями зависимостей.
- **Корневой `Makefile`**: переключатель `BACKEND=go|c` (Phase 8) убран
  — `build_backend` всегда собирает `src/backend-c`.
  `C_CROSS_COMPILE`/`C_SYSROOT`/`C_DEPS_IPK`/`C_DEPS_APK` переименованы
  в `CROSS_COMPILE`/`SYSROOT`/`DEPS_IPK`/`DEPS_APK`, безусловные. Все
  40 `config/*/*.config` лишились строк
  `GOOS=`/`GOARCH=`/`GOMIPS=`/`GOARM=`/`GO386=` — остались только
  `PLATFORM=`/`TARGET=`. `.config.example` переписан под C-переменные.
- **`.github/workflows/check.yml`**: Go-джобы (`check`/`test_backend`)
  убраны целиком, остался только `test_frontend`.
- **`.github/workflows/check-c.yml`**: `differential`-джоб больше не
  ставит Go — гоняет тот же `run_diff.sh`, теперь Go-независимый.
- **`.github/workflows/build.yml`**: шаг "Set up Go" убран. **Критичный
  момент, требовавший отдельного решения**: Go кросс-компилировался
  под все 40 целей автоматически через `GOOS`/`GOARCH`; у C такого
  эквивалента нет — нужен реальный per-target тулчейн + сисрут с
  собранными под целевую libc `libyaml`/`libpcre2`/`libmnl`/`libcurl`/
  `libcjson`, которого в этом CI нет (см. D-37/D-38: апстрим
  Entware/OpenWrt зеркала заблокированы, `ports.ubuntu.com`-обходной
  путь покрывает только dev-заголовки для arm64/armhf/riscv64, не
  полный тулчейн). Оставить `CROSS_COMPILE`/`SYSROOT` пустыми и просто
  собирать — значило бы молча получать host-x86_64 бинарник,
  промаркированный как бинарник целевой архитектуры: поломка
  корректности, а не сборки, и заведомо хуже, чем видимый отказ.
  Решение: шаг "Check cross-toolchain availability" безусловно
  выставляет `ready=false` для каждой цели с явным `::notice::`,
  реальная сборка/упаковка/выгрузка артефактов — под этим гейтом. Это
  осознанная, раскрытая регрессия покрытия CI-сборки (40 целей были
  "упакованы в CI" под Go, стали "пока не автоматизировано" под C) в
  обмен на корректность — не тихая потеря. Локальная сборка под
  реальную цель с руками заданными `CROSS_COMPILE`/`SYSROOT`
  продолжает работать как раньше.
- **`.gitlab-ci.yml`** (найден по ходу проверки, не упомянут явно ни в
  одной предыдущей фазе рерайта — зеркало GitLab CI, не связанное с
  активным GitHub-репозиторием этой сессии, но всё равно живой Go-код
  в дереве): `test_backend`-джоб полностью переписан под C
  (`alpine:3.21` + `build-base yaml-dev pcre2-dev libmnl-dev curl-dev
  cjson-dev`, `make CFLAGS_EXTRA=-Werror && make test`), пути
  `src/backend/**/*` заменены на `src/backend-c/**/*`. `build`-джоб
  собирал под `golang:1.23-alpine`, полагаясь на то же прозрачное
  Go-кросс-компилирование — при переходе на C-имидж получил тот же
  риск молчаливой промаркировки не того бинарника, что и
  `build.yml`, так что получил тот же защитный гейт: цикл по всем
  `config/*/*.config` теперь пропускает (не молча собирает) любую
  цель без `CROSS_COMPILE` в её `.config`, с явным `SKIP`-сообщением.
- **Дифференциальный набор** (`src/backend-c/tests/differential/`)
  целиком зависел от Go как живого оракула сравнения (`oracle_go`,
  `cache_oracle_go`, `dns_gen_go`, `dns_oracle_go`, плюс два
  Phase 1-спайка `spikes/{regex_corpus,yaml_emit}/*_go`). Перед
  удалением `src/backend` вживую в последний раз захвачен весь вывод
  Go (HTTP-контракт, config-фикстуры, rule matching, subscription
  parse, DNS wire, records cache, regexp2-корпус, yaml.v2-эмит) и
  заморожен под `golden/` (в `tests/differential/` и в обоих спайках)
  — побайтово идентичный C на момент захвата (последнее, что
  подтвердил финальный прогон D-44 перед этим изменением).
  `run_diff.sh`, `run_http_diff.sh` и оба spike `run.sh` переписаны
  сверять живой вывод C-инструментов против этих golden-снепшотов
  вместо живого прогона Go. Все Go-оракулы удалены.
  `tests/differential/corpus/dns_corpus.hex` (раньше перегенерировался
  каждый прогон удалённым уже `dns_gen_go` и потому был в
  `.gitignore`) стал закоммиченной замороженной фикстурой.

  Следствие, зафиксированное в D-45: эти наборы больше не могут
  поймать *новое* расхождение Go/C (Go больше нет) — теперь это
  регрессионные тесты против уже проверенного поведения C, ту же роль
  уже играет `parity-checklist.md`. Реальная регрессия в C всё ещё
  проявится диффом против `golden/`; просто без живой сверки с
  референсом. Явный, раскрытый компромисс завершения рерайта, а не
  недосмотр.

- **Документация**: `CLAUDE.md` переписан — Backend-раздел описывает
  C11-структуру (`src/backend-c/`), команды сборки/тестов, CI-раздел
  описывает все три актуальных workflow и честно раскрывает пробел
  packaging-матрицы; `AGENTS.md` — структура проекта и правила
  переориентированы на C-бэкенд как единственную продакшн-реализацию,
  "C rewrite ground rules" переименованы в "Backend behaviour
  contracts" (рерайт завершён, но контракты/golden-регрессии всё ещё
  обязательны); `README.md` уже не содержал упоминаний Go — правок не
  потребовалось. `migration-plan.md`'s статус-борд обновлён (Phase 9 —
  done). `decisions.md` получил запись **D-45** с полной мотивацией
  каждого решения выше.

### Финальная верификация после удаления

С `src/backend` полностью отсутствующим в рабочем дереве, с нуля
пересобрано и перепрогнано: `make CFLAGS_EXTRA=-Werror` (чистая
сборка), `make test`, `make sanitize` (0 находок), `make
static_analysis` (чисто), `make fuzz FUZZ_RUNS=200000` (2 цели,
400 000 прогонов, 0 крашей), `sudo -E sh tests/differential/run_diff.sh`
(все наборы OK, включая 44-шаговый HTTP-контракт и переконвертированные
golden-наборы match/subparse/dns/cache). Дополнительно проверена
корневая сборка+упаковка целиком: `config/openwrt/x86_64.config`
(сборка C-бинарника прошла; упаковка `.apk` уткнулась в отсутствие
`apk`-инструмента в песочнице — не регрессия, тот же пробел из Phase 8)
и `config/entware/mipsel-3.4_kn.config` (полный цикл до готового
`.ipk`, включая ENTWARE_KN-специфичный список интерфейсов). Все
workflow YAML (`check.yml`, `check-c.yml`, `build.yml`,
`.gitlab-ci.yml`) синтаксически валидны (`yaml.safe_load`).

## Нерешённое / перенесённое

- **Реальная on-device верификация Entware/OpenWrt не выполнена ни в
  одной фазе рерайта** — предопределённый, многократно
  задокументированный пробел этой песочницы (нет ни устройства, ни
  доступного тулчейна/feed-зеркала). Это преэкзистентный остаточный
  риск самой C-реализации, никак не усугублённый удалением Go —
  зафиксировано и в `parity-checklist.md`, и в D-45.
- **Поиск хука Keenetic RCI отложен**, а не найден — тот же
  преэкзистентный пробел.
- **Packaging-матрица `build.yml`/`.gitlab-ci.yml`'s `build`-джоб**
  теперь явно, а не молча, не автоматизирована для всех 40 целей до
  провижининга реальных per-target тулчейнов+сисрутов (см.
  `docs/c-rewrite/toolchains.md`). Локальная сборка под конкретную
  цель с руками заданным `CROSS_COMPILE`/`SYSROOT` не затронута.
- **Регрессионные наборы `match`/`subparse`/`dns`/`cache`/`regex`/`yaml`
  теперь сверяются с замороженным golden-снепшотом Go**, а не с живым
  Go — при будущем изменении ожидаемого поведения обновление
  `golden/`-файлов должно сопровождаться записью в `decisions.md`, а не
  быть тихим.

## Выполнение Definition of Done (spec §24)

- Backend полностью функционален на C11, Go отсутствует в дереве.
- Все контракт-тесты, юнит-тесты, дифференциальные/регрессионные
  наборы, санитайзеры и фаззинг — зелёные на чистой пересборке без Go.
- Чеклист паритета (`parity-checklist.md`) пройден по каждому пункту
  `compatibility-contract.md`, с найденным и исправленным реальным
  расхождением (список интерфейсов Keenetic).
- Финальное сравнение производительности задокументировано с цифрами
  (`tools/bench`), C превосходит Go по throughput и ресурсам на
  измеренной нагрузке.
- Долгий soak проведён (ограниченная по времени версия, раскрыто как
  таковая), без утечек и ошибок.
- Удаление Go — отдельный, чисто откатываемый коммит; вся документация
  проекта (`CLAUDE.md`, `AGENTS.md`, README, migration-plan.md,
  decisions.md) обновлена и согласована с реальным состоянием дерева.
- Единственные оставшиеся пробелы — преэкзистентные ограничения самой
  песочницы (нет реального железа/тулчейнов), явно раскрытые, а не
  скрытые, и не введённые этим изменением.
